# Генератор ТЗ для ИИ-ассистента

**Версия:** v1.0
**Владелец:** Алексей Чибирян
**Статус:** Active

**Теги:** `AI` `Prompt Engineering` `ТЗ` `AI Assistant` `Development` `CLEAR`

---

## 1. Цель

Промпт предназначен для генерации структурированной технической концепции ИИ-ассистента.

Он позволяет на основании информации о компании, целях проекта и необходимом функционале получить первоначальное ТЗ, включающее:

* функции ассистента;
* архитектуру;
* рекомендуемые технологии;
* интеграции;
* работу с базой знаний;
* безопасность;
* этапы разработки MVP;
* возможности масштабирования.

---

## 2. CLEAR

### Task

Подготовить техническую концепцию ИИ-ассистента.

### Context

ИИ-ассистент разрабатывается для конкретной компании и должен решать определённые бизнес-задачи.

### Input

На вход передаются:

* отрасль;
* цель ассистента;
* пользователи;
* задачи;
* интеграции;
* источник базы знаний.

### Output

Структурированное техническое задание с описанием функций, архитектуры, технологий, интеграций, безопасности и этапов разработки.

---

## 3. Шаблон промпта

```text id="bj6c4s"
Ты — архитектор ИИ-систем.

Подготовь техническую концепцию ИИ-ассистента для компании.

Контекст:
- отрасль: {industry}
- цель ассистента: {goal}
- пользователи: {users}
- основные задачи: {tasks}
- необходимые интеграции: {integrations}
- источник базы знаний: {knowledge_base}

Опиши:
1. основные функции;
2. архитектуру решения;
3. рекомендуемые технологии;
4. работу с базой знаний;
5. интеграции;
6. меры безопасности;
7. этапы разработки MVP;
8. возможности дальнейшего масштабирования.

Формат ответа:
структурированное ТЗ с заголовками и краткими пояснениями по каждому пункту.
```

---

## 4. Переменные

| Переменная         | Описание                                                   |
| ------------------ | ---------------------------------------------------------- |
| `{industry}`       | Сфера деятельности компании                                |
| `{goal}`           | Основная цель ИИ-ассистента                                |
| `{users}`          | Пользователи системы                                       |
| `{tasks}`          | Задачи, которые должен выполнять ассистент                 |
| `{integrations}`   | Сервисы и системы, с которыми необходимо взаимодействовать |
| `{knowledge_base}` | Источники информации для базы знаний                       |

---

## 5. Пример входных данных

```text id="ukpshs"
industry = салон красоты

goal = автоматизация консультаций и записи клиентов

users = клиенты салона и администраторы

tasks = консультация по услугам, подбор мастера,
запись клиента, перенос и отмена записи

integrations = CRM, Telegram, Google Calendar

knowledge_base = сайт салона, прайс-лист,
информация об услугах и мастерах
```

## 6. Пример ожидаемого результата

### ИИ-ассистент салона красоты

**Основные функции:**

* консультирование клиентов;
* ответы на вопросы об услугах и стоимости;
* подбор подходящего мастера;
* проверка свободного времени;
* запись клиента;
* перенос и отмена записи.

**Архитектура:**

`Пользователь → сайт/Telegram → Backend → LLM → RAG → база знаний`

Для записи клиентов backend взаимодействует с CRM и календарём салона.

**Рекомендуемые технологии:**

* Python;
* FastAPI;
* OpenAI API;
* ChromaDB;
* PostgreSQL;
* Telegram Bot API;
* CRM API.

**Безопасность:**

* защита API-ключей;
* разграничение доступа;
* защита персональных данных;
* журналирование действий.

**Этапы MVP:**

1. Подготовка базы знаний.
2. Создание RAG-системы.
3. Подключение LLM.
4. Создание пользовательского интерфейса.
5. Интеграция с CRM и календарём.
6. Тестирование.
7. Развёртывание MVP.

# 7. Тест-кейсы

## Тест-кейс №1 — Салон красоты

### Вход

```text id="2h7fvs"
industry = салон красоты
goal = автоматизация записи клиентов
users = клиенты и администраторы
tasks = консультация, подбор мастера, запись
integrations = CRM, Google Calendar
knowledge_base = сайт, прайс-лист, информация о мастерах
```

### Ожидаемый результат

Ассистент должен консультировать клиента, подбирать мастера, проверять свободное время и создавать запись.

### Критерий успешности

В ответе присутствуют функции, архитектура, технологии, интеграции, безопасность и этапы MVP.

---

## Тест-кейс №2 — Интернет-магазин

### Вход

```text id="7yt3rt"
industry = интернет-магазин электроники
goal = автоматизация консультаций покупателей
users = посетители интернет-магазина
tasks = поиск товаров, сравнение характеристик,
ответы на вопросы, рекомендации
integrations = CMS, CRM
knowledge_base = каталог товаров, характеристики, FAQ
```

### Ожидаемый результат

Ассистент должен искать товары, сравнивать модели и давать рекомендации на основании каталога.

### Критерий успешности

Система должна использовать актуальную информацию из базы знаний и не придумывать отсутствующие характеристики товаров.

---

## Тест-кейс №3 — HR-ассистент

### Вход

```text id="ft4xip"
industry = HR
goal = автоматизация первичного отбора кандидатов
users = HR-менеджеры
tasks = анализ резюме, сравнение с вакансией,
формирование рейтинга кандидатов
integrations = Gmail, Google Sheets
knowledge_base = вакансии и требования к кандидатам
```

### Ожидаемый результат

Ассистент должен анализировать резюме, сравнивать данные кандидата с требованиями вакансии и формировать рейтинг соответствия.

### Критерий успешности

Ассистент объясняет причины выставленного рейтинга и не принимает окончательное решение о найме вместо HR-менеджера.

---

## 8. Критерии качества

Промпт считается успешно протестированным, если:

* результат соответствует поставленной задаче;
* модель использует переданные переменные;
* соблюдается заданная структура ответа;
* обязательные разделы не пропускаются;
* промпт работает для разных отраслей;
* для нового проекта достаточно изменить значения переменных.
