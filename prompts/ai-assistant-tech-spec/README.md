# Генератор ТЗ для ИИ-ассистента

**Версия:** v1.0
**Владелец:** Алексей Чибирян
**Статус:** Active

**Теги:** `AI` `Prompt Engineering` `ТЗ` `AI Assistant` `Development` `CLEAR`

## 1. Цель

Промпт предназначен для генерации структурированного технического задания на разработку ИИ-ассистента.

Позволяет на основе описания бизнеса, целей проекта и требуемого функционала получить первоначальную концепцию системы: функции, архитектуру, технологии, интеграции, работу с базой знаний, безопасность и этапы разработки MVP.

## 2. Шаблон промпта

Ты — архитектор ИИ-систем.

Подготовь техническую концепцию ИИ-ассистента для компании.

### Контекст

* отрасль: `{industry}`
* цель ассистента: `{goal}`
* пользователи: `{users}`
* основные задачи: `{tasks}`
* необходимые интеграции: `{integrations}`
* источник базы знаний: `{knowledge_base}`

### Опиши

1. основные функции;
2. архитектуру решения;
3. рекомендуемые технологии;
4. работу с базой знаний;
5. интеграции;
6. меры безопасности;
7. этапы разработки MVP;
8. возможности дальнейшего масштабирования.

### Формат ответа

Структурированное ТЗ с заголовками и краткими пояснениями по каждому пункту.

---

# 3. Пример входных данных

```text
industry = салон красоты

goal = автоматизация консультаций клиентов и записи на услуги

users = клиенты салона и администраторы

tasks = консультация по услугам, подбор мастера, запись клиента, перенос и отмена записи

integrations = CRM, Telegram, Google Calendar

knowledge_base = сайт салона, прайс-лист, информация об услугах и мастерах
```

# 4. Пример ожидаемого результата

## ИИ-ассистент салона красоты

**Основные функции:**

* консультирование клиентов по услугам;
* ответы на вопросы о стоимости;
* подбор подходящего мастера;
* проверка свободного времени;
* запись клиента;
* перенос и отмена записи;
* передача сложного запроса администратору.

**Архитектура:**

Пользователь → интерфейс сайта/Telegram → backend → LLM → RAG → база знаний.

Для записи клиентов backend взаимодействует с CRM и календарём салона.

**Технологии:**

* Python;
* FastAPI;
* OpenAI API;
* ChromaDB;
* PostgreSQL;
* Telegram Bot API;
* CRM API.

**Безопасность:**

* разграничение прав доступа;
* защита API-ключей;
* минимизация хранения персональных данных;
* журналирование действий системы.

**MVP:**

1. Подготовка базы знаний.
2. Разработка RAG-поиска.
3. Подключение LLM.
4. Создание интерфейса.
5. Интеграция с системой записи.
6. Тестирование.
7. Развёртывание MVP.

# 5. Тест-кейсы

## Тест-кейс №1 — Салон красоты

**Вход:**

```text
industry = салон красоты
goal = автоматизация записи клиентов
users = клиенты и администраторы
tasks = консультация, подбор мастера, запись
integrations = CRM, Google Calendar
knowledge_base = сайт, прайс-лист, информация о мастерах
```

**Ожидаемый результат:**

Модель должна предложить ИИ-ассистента, который консультирует клиента, подбирает мастера, проверяет доступное время и создаёт запись через CRM или календарь.

**Критерий успешности:** в ответе присутствуют функции ассистента, архитектура, технологии, интеграции, безопасность и этапы MVP.

---

## Тест-кейс №2 — Интернет-магазин

**Вход:**

```text
industry = интернет-магазин электроники
goal = автоматизация консультаций покупателей
users = посетители интернет-магазина
tasks = поиск товаров, сравнение характеристик, ответы на вопросы, рекомендации
integrations = CMS, CRM
knowledge_base = каталог товаров, характеристики, FAQ
```

**Ожидаемый результат:**

Модель должна предложить ассистента, способного искать товары по запросу пользователя, сравнивать модели и рекомендовать подходящий вариант на основании базы товаров.

**Критерий успешности:** решение предусматривает работу с актуальным каталогом и не позволяет модели придумывать отсутствующие характеристики товаров.

---

## Тест-кейс №3 — HR-ассистент

**Вход:**

```text
industry = HR
goal = автоматизация первичного отбора кандидатов
users = HR-менеджеры
tasks = анализ резюме, сравнение с вакансией, рейтинг кандидатов
integrations = Gmail, Google Sheets
knowledge_base = вакансии, требования к кандидатам
```

**Ожидаемый результат:**

Модель должна предложить систему, которая получает резюме, извлекает информацию о кандидате, сравнивает её с требованиями вакансии и формирует рейтинг соответствия.

**Критерий успешности:** система должна объяснять причины выставленного рейтинга и не принимать окончательное решение о найме вместо HR-специалиста.

# 6. Критерии качества промпта

Промпт считается успешно протестированным, если:

* результат соответствует поставленной задаче;
* учитываются переданные входные переменные;
* структура ответа одинакова для разных предметных областей;
* модель не игнорирует обязательные разделы;
* результат можно использовать как основу для дальнейшей разработки;
* при изменении входных данных промпт не требует изменения своей основной структуры.
